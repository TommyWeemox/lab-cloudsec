# S02 : Terraform, state distant et plateforme commune

Date : 2026-11-18

## Fait
Backend Terraform durci, créé par `scripts/azure/bootstrap-state.ps1` : compte de stockage
dédié (clé partagée et accès public désactivés, TLS 1.2, historique des versions, rétention
de 14 jours), rôle Storage Blob Data Contributor et verrou CanNotDelete.

Première racine Terraform `infra/platform/` (state `platform.tfstate`) :
- groupe de ressources `rg-lab-platform-frc` ;
- espace Log Analytics `law-lab-platform-frc` (30 jours de rétention, plafond de 0,1 Go/jour) ;
- budget mensuel de 40 EUR `budget-lab-monthly`, avec des seuils à 50, 75 et 100 % en
  dépense réelle et à 100 % en prévision.

Apply : 3 ressources créées. Un `terraform plan` relancé ensuite répond « No changes »,
donc aucune dérive.

## Appris
Backend distant avec authentification Entra (`use_azuread_auth`) : sans clé partagée, être
Propriétaire ne suffit pas, il faut un rôle de données sur le compte. Un bloc backend
n'accepte pas de variables. azurerm 4.x exige l'abonnement (`ARM_SUBSCRIPTION_ID`).
Variables avec validation, locals, source de données, bloc `dynamic`. Le fichier
`.terraform.lock.hcl` est commité, le state ne l'est jamais. Les données non secrètes mais
privées (adresse d'alerte) passent par `TF_VAR_*`.

## Blocages
PowerShell 5.1 : accents lus de travers dans un script UTF-8 sans BOM, et parenthèses de
`--query "length(@)"` qui cassent l'appel à `az`. Il faut attendre la propagation du rôle
de données avant de créer le conteneur.
